# Native kernel IPC fixtures

These checked-in packets are generated by native MSVC code using the repository's
current serialization declarations and cereal 1.3.2. They are independent of the
UI protocol writer. Each `.bin` contains the four-byte, little-endian body length
followed by `cereal::BinaryOutputArchive(PacketHeader, payload)`, as used by
`CommonUtilities/pipe/Pipe.h`. The adjacent `.json` is a readable cereal JSON
serialization of exactly the same header and payload. `manifest.json` records
source-header hashes, dependency provenance, compiler version, and packet hashes.

`Generate.cpp` defines all fixture values. Color inputs use integer RGB channels
divided by `255.f`, with an explicit float alpha, matching the native UI contract.
The JSON color keys are `s.r`, `s.g`, `s.b`, and `s.a` because those are the native
`CEREAL_NVP` expressions. Optional values use `nullopt`/`data`; widgets use
`index`/`data` for the native `std::variant` representation.

| Packet | Contents |
| --- | --- |
| `full-spec.bin` | Token 17, PID 4242, adapter 7, every preference field, two graph metrics, one readout metric, both variant alternatives, distinct colors and label flags |
| `empty-spec.bin` | Token 19, same preferences, absent PID and adapter, empty widgets |
| `introspect.bin` | Token 23, three metrics with availability and stats, four stats, two adapters, system device 12, default adapter 9, three availability reasons, empty units |
| `open-session.bin` | Token 29, frontend PID 54321 |
| `open-session-response.bin` | Token 29, kernel PID 65432 and four distinct version/build strings |
| `bind-hotkey.bin` | Token 31, key 42, modifiers 2 and 4, action 3 |

All headers have successful statuses, version 1, and `ActionRequest` packet type
0. The response fixtures call the real native `MakeResponseHeader`, which
preserves the request type.

## Regenerate

From the repository root, in PowerShell with Visual Studio C++ tools installed:

```powershell
./IntelPresentMon/AppWinUICpp/Tests/NativeFixtures/Generate.ps1 -DownloadCereal
```

Alternatively pass `-CerealInclude <path-to-include>` for existing cereal 1.3.2 headers,
and optionally `-VisualStudioPath <installation-root>`. `-DownloadCereal` downloads
the pinned official archive only if the headers do not already exist, checks its
SHA256, and extracts it under the ignored `build/tools/native-fixtures` directory.
No packages or dependencies are installed globally.

The script includes `Packet.h`, `PresentMonAPI.h`, and `Geometry.h` directly.
Including complete action headers would pull in unrelated kernel, D3D, logging,
and Boost dependencies. Instead, the script extracts the full action data
declarations and their `serialize` bodies verbatim from `PushSpecification.h`,
`Introspect.h`, `OpenSession.h`, and `BindHotkey.h` each time it runs. It similarly
extracts the actual `OverlayPosition` declaration and the existing macros that
generate `AxisAffinity`; it does not substitute integer aliases or hand-code
enum definitions. The generated header stays in the ignored build directory.
Native compile-time assertions check the scalar widths, underlying enum types,
cereal size width, and byte order relied on by the wire protocol.

After the native build succeeds, the executable generates every packet and then
runs a separate verification pass that checks framing, fully consumes the native
deserialization, and compares its reserialization byte for byte. UI protocol
checks compare outbound packets and decode inbound packets against these files.
The native roundtrip checks alone do not establish end-to-end UI interoperability.
